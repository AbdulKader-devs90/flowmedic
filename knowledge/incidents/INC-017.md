## Symptoms
The Orders API is returning HTTP 500 to all callers since about 10:40. server.log shows the JDBC adapter pool has 0 connections available. Platform is webMethods Integration Server on Linux, production cluster.
Session outcome: escalate

## Root cause
db_blocking_lock, jdbc_pool_exhausted

## Resolution steps
1. [read] Check pool usage against max size in the Admin UI.
   Observed: Admin UI > Adapters > JDBC Adapter > Connections > OrdersApi.connections:OrdersDB_Pool  Min 0 | Max 15 | In use 15 | Available 0 | Block timeout 10000 ms | Waiting requests 37`
2. [read] Take a thread dump and count threads in getConnection.
   Observed: is-node-a thread dump 10:44: 37 HTTP Handler threads waiting in JDBCConnectionPool.getConnection, 15 in T4CPreparedStatement.executeForRows (OrdersApi.db:insertOrder)
3. [read] Ask the DBA for long-running sessions from the IS host, their SQL, and SID.
   Observed: BA: SID 1412 ACTIVE elapsed 00:07:41, SELECT ... FROM ORDER_REPORT_V (ad-hoc report). 14 other sessions waiting on SID 1412 (enq: TX - row lock contention)

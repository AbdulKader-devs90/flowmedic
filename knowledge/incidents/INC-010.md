# INC-010 Universal Messaging session leak grows thread count

## Symptoms

Connections from each IS node to the UM port grow from about 150 at start to over 1,000 after two weeks; IS threads grow with them.

## Root cause

A JMS trigger reconnect path opened new sessions without closing the old ones.

## Resolution steps

1. [read] Count connections to the UM port on each node (ss -tnp, match both IPv4 and [::ffff:] forms).
2. [read] Log the count on a schedule to see the trend.
3. [change] Planned restart of the node with the highest count, per RB-14.
4. [change] Raise a vendor case with the trend; review the trigger reconnect settings.

## Verification

Connection count stays flat for days.

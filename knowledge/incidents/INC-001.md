# INC-001 Node not responding: auth hashing thread pile-up with DB login timeouts

## Symptoms

is-node-b stopped answering pings. Load average above 1000 on 4 cores. Over 1,200 threads, most HTTP handlers from the API gateway. Swap in use.

## Root cause

Every gateway call used Basic auth, so IS hashed the password (PBKDF2) on each request and CPU saturated. Threads piled up, the internal DB pool timed out on login, and leftover DB sessions kept locks after forced restarts.

## Resolution steps

1. [read] Take 2-3 thread dumps; count threads in PBKDF2KeyImpl.deriveKey and in getConnection.
2. [read] grep server.log for 'Login has timed out' and 'fail-fast'; ask the DBA for IS schema sessions by machine and blockers.
3. [change] Block or throttle gateway traffic to the node (firewall or gateway throttle).
4. [change] Follow RB-14: stop IS, DBA clears leftover sessions, start nodes one at a time.
5. [change] Cap the server thread pool and add per-API throttling; plan mTLS between gateway and IS.

## Verification

Threads in deriveKey near zero, no new login timeouts for 30 minutes, ping returns 200.

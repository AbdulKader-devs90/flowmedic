# INC-003 JDBC adapter pool exhausted by slow backend queries

## Symptoms

Orders API returns 500. server.log shows the adapter pool at 0 available and threads waiting in getConnection.

## Root cause

A backend report query ran for minutes and held connections; the pool (max 15) filled up and new calls waited until the block timeout.

## Resolution steps

1. [read] Check pool usage against max size in the Admin UI; take a thread dump and count threads in getConnection.
2. [read] Ask the DBA for long-running sessions from the IS host and their SQL.
3. [change] DBA ends the runaway session only if the owning service is gone; otherwise cancel the service thread in IS.
4. [change] Disable and enable the adapter connection to reset the pool; raise max size only after checking DB session limits.

## Verification

Pool usage back under 50%; Orders API returns 200.
